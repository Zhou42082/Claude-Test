# 测试指南

演示模式不需要 Home Assistant 和任何真实设备：网关内置一套演示设备（覆盖小米、华为、涂鸦、乐橙、德施曼），并提供「演示工具」模拟漏水、门铃等事件。下面的清单在演示模式下逐项验证。

## 1. 准备

任选一种方式启动演示网关。本地没有 Docker 的话，用云端方式，见 [cloud-demo.md](cloud-demo.md)，然后直接跳到下面的「客户端」。

> **最快的方式：不启动网关。** App 首次打开时点「体验演示模式」，或打开 GitHub Pages 上的网页版（见 cloud-demo.md），用的是 App 内置的演示网关。下面的清单基本都适用，区别是：没有「连接」一节的内容；开锁 PIN 输错不会锁定；刷新页面或重启 App 后数据恢复初始状态，告警不保留。

**方式 A：Docker（推荐，网关和网页版一起启动）**

```bash
docker compose -f docker-compose.demo.yml up --build
```

**方式 B：本机 Python**

```bash
cd backend && pip install -e ".[dev]"
```

```bash
GATEWAY_TOKEN=devtoken GATEWAY_UNLOCK_PIN=2468 GATEWAY_ADAPTERS=mock GATEWAY_DATA_DIR=./data uvicorn gateway.main:app --factory --host 0.0.0.0 --port 8000
```

方式 B 不带网页版；需要网页版时先在 `mobile/` 下执行 `flutter build web --release`，再加上环境变量 `GATEWAY_WEB_DIR=../mobile/build/web`。

然后选择客户端：

| 客户端 | 获取方式 | 网关地址 |
| --- | --- | --- |
| 网页版 | 浏览器打开 `http://<网关IP>:8000/`（手机和电脑都行，需在同一局域网） | 自动填好 |
| Android APK | GitHub 仓库 → Actions → 最新一次 CI → Artifacts 下载 `smart-home-apk`，解压后安装 `app-release.apk`（需允许安装未知来源应用） | `http://<网关IP>:8000` |
| 开发调试 | `cd mobile && flutter run` | Android 模拟器用 `http://10.0.2.2:8000` |

演示参数：令牌 `devtoken`，门锁开锁 PIN `2468`。

> 网关 IP 是运行网关那台电脑的局域网地址（如 192.168.1.10），手机和电脑要连同一个 Wi-Fi。电脑防火墙需要放行 8000 端口。

## 2. 功能清单

每一项后面是预期结果。

### 连接

- [ ] 首次打开显示「连接家庭网关」，填入令牌后点「测试并保存」 → 提示「连接成功，发现 N 个设备」，进入首页
- [ ] 故意填错令牌 → 提示「连接失败：令牌无效，请在设置中检查」
- [ ] 停掉网关 → 首页顶部出现「与网关的连接已断开，正在自动重连」；重新启动网关后自动恢复
- [ ] 关闭 App 再打开 → 不需要重新输入令牌

### 首页

- [ ] 底部导航：首页 / 场景 / 告警 / 我的
- [ ] 顶部问候语（按时间显示早上好、晚上好等）和日期
- [ ] 概览卡片：室内温度、PM2.5 和空气质量、运行中的设备数、在线设备数；右下角显示「一切正常」或需要注意的事（设备报警、告警待查看、设备离线）
- [ ] 「设备」下方的房间标签：全部 / 卧室 / 厨房 / 客厅 / 门口，标签上显示设备数量
- [ ] 平台筛选：点「全部平台」→ 选「乐橙」只剩门口摄像头，点筛选标签上的 × 恢复
- [ ] 卡片上的开关直接控制灯、插座、风扇、净化器；开启后卡片换成该类设备的颜色（灯暖黄、空调蓝、窗帘青绿……）
- [ ] 离线设备（厨房门窗传感器）显示为半透明、状态「离线」
- [ ] 漏水、烟雾报警或门锁卡住时，对应卡片变红
- [ ] 手机切换深色模式 → App 跟随变为深色

### 设备控制（点卡片打开控制面板）

- [ ] 控制面板的滑块、开关、模式按钮使用该设备的颜色

- [ ] 客厅吸顶灯：拖动亮度 / 色温滑块，松手后卡片上的亮度更新
- [ ] 客厅空调：+ / − 调温度，切换制冷、制热等模式
- [ ] 客厅窗帘：打开 / 暂停 / 关闭，拖动开合度
- [ ] 卧室空气净化器：显示 PM2.5 和空气质量等级、滤芯剩余；切换自动 / 睡眠 / 强力模式，调风速
- [ ] 卧室温湿度计、水浸、烟雾传感器：只显示读数，没有控制项

### 门锁

- [ ] 入户门锁显示「已上锁 · 电量 76%」
- [ ] 点「远程开锁」→ 弹出 PIN 输入框；输入错误 PIN → 提示「开锁 PIN 错误」
- [ ] 输入 `2468` → 状态变为「未上锁」，图标变红，告警里多一条「门锁已打开」
- [ ] 点「上锁」不需要 PIN，状态恢复「已上锁」
- [ ] 连续输错 5 次 PIN → 提示「PIN 错误次数过多，请 N 秒后再试」（之后需等 5 分钟或重启网关）

### 摄像头

- [ ] 门口摄像头面板显示当前画面，「刷新画面」可以重新获取
- [ ] 点云台方向键 → 约 1 秒后画面自动刷新，画面中的门随之移动
- [ ] 演示摄像头不支持实时视频，显示「该摄像头不支持实时视频」（接入乐橙真实摄像头后会出现「实时画面」按钮）

### 场景

- [ ] 首页「常用场景」和底部「场景」页都有回家 / 睡眠 / 离家三个场景
- [ ] 点「离家」→ 提示「已执行「离家」」；灯、空调、插座、风扇关闭，窗帘关闭，门锁上锁
- [ ] 点「回家」→ 客厅灯和空调打开，窗帘打开

### 告警（首页右上角烧瓶图标，或「我的 → 演示工具」）

| 演示事件 | 预期 |
| --- | --- |
| 厨房漏水 | 红色弹窗「厨房 · 厨房水浸传感器：检测到漏水」，停留 10 秒，底部「告警」角标 +1，首页概览显示「1 台设备报警」 |
| 客厅烟雾报警 | 红色弹窗「检测到烟雾」 |
| 有人按门铃 | 弹窗「有人按门铃」；摄像头面板出现「最近门铃 HH:mm」 |
| 门口有人经过 | 不弹窗（提示级别），告警列表出现「检测到移动」；摄像头卡片显示「检测到移动」，15 秒后恢复。5 分钟内重复触发不会重复告警 |
| 门锁卡住 | 红色弹窗「门锁卡住，请检查」 |
| 门锁电量低 | 弹窗「电量低（15%），请更换电池或充电」 |
| 净化器滤芯耗尽 | 弹窗「滤芯剩余 5%，请及时更换」，净化器面板滤芯进度条变红 |
| 摄像头离线 | 弹窗「设备离线」，摄像头卡片变为离线 |
| 全部恢复初始状态 | 所有设备回到初始状态，不产生新告警 |

- [ ] 同一事件连续触发两次（如先「厨房漏水」再「厨房漏水」）→ 只告警一次；先「全部恢复」再触发才会再次告警
- [ ] 点底部「告警」或弹窗上的「查看」→ 告警列表按今天 / 昨天分组，最新在上；进入后角标清零；点某条告警打开对应设备
- [ ] 重启网关（方式 B 设置了 `GATEWAY_DATA_DIR`，Docker 方式自动持久化）→ 告警记录仍在
- [ ] 重启 App → 已读过的告警不再计入未读

```bash
cd backend && pytest
```

```bash
cd mobile && flutter test
```

每次推送到 GitHub 后，CI 会运行网关测试、App 测试，构建 APK、网页版和 Docker 镜像，并对 Docker 镜像做演示模式的冒烟测试。

## 4. 接入真实设备后的测试

接入方式见 README「接入真实设备」。真实设备上额外需要验证：

- 设备名称、房间（来自 HA 的「区域」）、平台标签是否正确；平台识别不对时调整 `backend/gateway/adapters/ha_mapping.py` 的 `INTEGRATION_PLATFORMS` / `MANUFACTURER_HINTS`
- 净化器的 PM2.5、滤芯寿命是否合并到了净化器卡片上
- 乐橙摄像头：实时视频（需在乐橙集成中开启视频流）、云台、门铃和移动侦测（需在乐橙集成里开启告警推送）
- 德施曼门锁：开锁需要 HA 主机在门锁蓝牙范围内；不支持远程上锁，点「上锁」会提示失败
- 用手机流量（不连家里 Wi-Fi）访问需要先配置远程访问，见 `docs/architecture.md` 第 7 节
